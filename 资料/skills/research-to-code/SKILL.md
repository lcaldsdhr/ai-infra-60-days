# 从查证到实现

把技术未知项变成有依据的实现选择，并交付可验证的代码。遵守用户指定的技术栈、范围和项目约定。

## 确定目标

检查项目说明、适用的 AGENTS.md、相关代码、实际依赖版本和检查命令。用具体行为描述目标与验收方式，只追问会改变实现的缺失信息。尚未确定目标项目或功能时，先形成可用结论或候选方案，询问必要信息，不自行创造项目任务。

## 查证关键未知项

优先查证会改变接口、依赖、数据格式或验证方式的问题。已有证据足够时直接推进，不要求每次联网或生成报告。

- 依据项目实际版本使用官方文档、源码或原始论文。需要当前信息时核对日期与版本；用最新版文档解释旧版本前先确认兼容性。
- 打开并阅读支持具体结论的原始内容，不把搜索摘要作为已核实依据。
- 对关键判断记录：问题、来源链接及版本或日期、发现、对实现的影响。区分来源事实、推断和待验证假设。
- 来源冲突时检查版本、环境与前提；能用本地小实验解决时优先实验。仍未解决则说明不确定性及影响。
- 剩余未知项不再影响验收，或可以用本地验证解决时结束检索。缺少关键证据时说明阻碍，选择有依据的保守方案或询问必要信息。

## 实现与验证

简述实现选择，沿用项目结构完成改动。仅在真实权衡影响决策时比较方案。

将关键假设变成可观察的检查，例如返回值、错误输入、版本兼容或相关回归测试。先运行直接覆盖目标行为的最小检查，再运行项目要求的检查。失败时根据证据定位原因；新证据推翻方案时更新决策。遇到相同阻碍且没有新证据时停止盲目重试，说明原因。

仅在重复操作确实需要时新增脚本或持久化资料。此 skill 不授予发布、部署、发送消息或更改外部账号状态的权限。

## 交付

说明实现了什么、关键证据如何影响选择、实际验证及结果、剩余不确定性。引用支持关键外部结论的直接来源，并提供改动文件链接。未运行的检查明确标注，不以“应当通过”代替实际结果。简单任务可用一段话完成。
