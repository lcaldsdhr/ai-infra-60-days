# 从高引用 arXiv 论文学习技术图绘制风格

> 查询与视觉核验日期：2026-10-13。范围：AI Infra、LLM、Agent 方法与 RL。
> 方法：核对论文身份与引用索引，下载作者 PDF，用 Poppler 渲染指定页并逐图查看；下面的风格判断是本次视觉分析，不是作者宣称的设计原则。
> 本次只研究和记录，不重绘已有博客图片，不修改全局作图技能。图的质量不能由论文引用数证明，也不能推断这些论文因图画得好而获得高引用。

## 1. 样本与选取依据

“高引用”在这次研究中的筛选门槛为索引引用数至少 1,000；这是取样规则，不是全领域排名。arXiv 提供论文，引用量来自另一个索引。不同索引不混合排名，数字不等同 Google Scholar；原始查询链接与身份核验见[引用量证据](arxiv-figure-style-citation-evidence.md)。

| 论文 | 本次引用量快照 | 视觉检查对象 | 优先学习的图法 |
| --- | --- | --- | --- |
| [Attention Is All You Need](https://arxiv.org/abs/1706.03762) | 196,585 · Semantic Scholar | v7，Figure 1，PDF 第 3 页 | 用结构、残差路径和重复单元表示架构 |
| [LoRA](https://arxiv.org/abs/2106.09685) | 24,226 · Semantic Scholar | v2，Figure 1，PDF 第 1 页 | 用形状与两条支路突出关键变化 |
| [FlashAttention](https://arxiv.org/abs/2205.14135) | 5,550 · Semantic Scholar | v2，Figure 1，PDF 第 2 页 | 内存层级、分块机制与实验证据组合 |
| [PagedAttention / vLLM](https://arxiv.org/abs/2309.06180) | 1,702 · OpenAlex | 查询时 PDF，Figures 4–5，第 5 页 | 将系统架构和局部机制拆成独立图 |
| [ReAct](https://arxiv.org/abs/2210.03629) | 12,411 · Semantic Scholar | 查询时 PDF，Figure 1，第 2 页 | 相同任务下的轨迹对照与局部高亮 |
| [DeepSeekMath](https://arxiv.org/abs/2402.03300) | 未核实；不计入高引用样本 | 查询时 PDF，Figure 4，第 13 页 | PPO / GRPO 同构布局突出差异 |

DeepSeekMath 作为与当前 RL 学习有关的补充图例。其引用数查询出现限流和索引身份不匹配，不能拿错误记录凑数。六篇均查看了 PDF 原图；对未固定版本的 PDF，后续页码可能随版本变化，应以图号定位。

## 2. 原图中真正值得学的地方

### Transformer：用图的拓扑承载信息

Figure 1 将 encoder、decoder 并置，沿竖直方向表达计算路径；重复单元使用包围结构与 `N×`，残差由绕行箭头表示。浅色区分模块类别，而不是装饰整张画布。图内只放模块名和必要输入输出，解释放在 caption 与正文。[原图：PDF 第 3 页](https://arxiv.org/pdf/1706.03762v7#page=3)

可迁移做法：重复 worker 不需要画十遍；用少量实例与省略号表达规模。共享部分保持相同位置，不同路径通过连线体现，减少段落式说明。

### LoRA：形状本身说明结构变化

Figure 1 用主权重和低秩分支汇合到输出，蓝色与橙色区分两类参数；窄的中间维度与 `r` 标注表达低秩瓶颈。冻结/训练差异主要通过分支结构和 caption 交代，而不是长解释框。[原图：PDF 第 1 页](https://arxiv.org/pdf/2106.09685v2#page=1)

可迁移做法：画关键变化时保留完整的输入—操作—输出。容量、维度或所有权如果能用几何结构表达，就不要仅依赖文字列举。形状是机制编码，不能任意变形而暗示错误比例。

### FlashAttention：信息密度高，但每一块都服务同一论点

Figure 1 同时包含内存层级、分块与拷贝路径、运行时间对照。不同颜色分别表达层级或循环身份，箭头有具体对象与方向，虚线框标出关键中间矩阵。右侧有带单位的结果图，与机制说明相邻。[原图：PDF 第 2 页](https://arxiv.org/pdf/2205.14135v2#page=2)

可迁移做法：增加信息时，优先加状态、层级、动作和可验证证据。没有自己的测量数据时只能画机制，不能照搬其性能数字到我们的系统，也不能用概念条带冒充测量结果。

### PagedAttention：架构图与寻址机制图分工

Figure 4 显示 scheduler、cache manager 与 worker 的关系；Figure 5 则聚焦一个 query 如何面对非连续的 KV blocks。两张小图分别回答“组件怎么协作”和“局部操作怎么执行”，没有强行融合成一张总览海报。[原图：PDF 第 5 页](https://arxiv.org/pdf/2309.06180#page=5)

可迁移做法：内存图采用明确 buffer/block 边界、空位和对象标识。箭头必须指向实际块，不能只是连接两个文字框。区分逻辑顺序与物理布局，避免用连续视觉排列暗示物理连续性。

### ReAct：高密度可以来自证据，而不是更多装饰

Figure 1 比较同一任务的多种方法，保留 Thought、Act、Obs 的具体轨迹，局部着色指出支持判断的信息和失败步骤，结果标记帮助定位成功/失败。它并不朴素，也不依赖大量流程箭头。[原图：PDF 第 2 页](https://arxiv.org/pdf/2210.03629#page=2)

可迁移做法：Agentic RL 图可以保留一段短的真实或明确标注为教学的工具轨迹，把决定下一步的 observation 高亮。无需将每一轮都简化成重复方框，也不应让整段文本染色。原图文字密集，中文博客应缩减到能在正常阅读宽度看清的少数步骤。

### DeepSeekMath：同构对照，比两个独立流程更好比较

Figure 4 将 PPO、GRPO 上下排布，复用 policy、reference、reward 的位置与角色颜色。GRPO 的多个输出、奖励和优势用列状结构表达，差异集中在 value/GAE 与 group computation 的路径。[原图：PDF 第 13 页](https://arxiv.org/pdf/2402.03300#page=13)

可迁移做法：正确/错误、同步/异步、PPO/GRPO 应在共同骨架上只改变关键部件。颜色要有角色含义，且具体实现可能与论文配方不同，必须按所讲版本核对。

## 3. 对当前四张报错图的启发

| 当前主题 | 更有价值的新增信息 | 避免继续增加的内容 |
| --- | --- | --- |
| 内存正确性 | 合法地址范围、同一地址的生命周期、线程读改写顺序、寻址契约 | 每个子图重复完整工具清单与排查流程 |
| OOM | 主要占用者的关系；有实测时加入阶段峰值/长度曲线 | 概念条带配上虚构数值；把等长条带误当等占用 |
| 异步与 NCCL | 共用时间参考、真实发生点、发现点、缺席 rank 与等待区 | 将虚线既当时间参考又当因果箭头；重复“报错不等于根因” |
| verl 样本对齐 | 一个最小错配实例、uid 组边界、字段索引映射 | 将样本对齐、token shift、工具 mask、权重版本都挤在一个图里 |

例如，DataProto 图可以用正确与错误两张同构表，保留四行样本、uid 和两个错配高亮；token 对齐单独成图。这样新增信息会提高辨识度，而不是让字号更小。

## 4. 后续作图准则：学术机制图，而不是纯极简或海报

以下是本次研究后提出的工作准则，不是某篇论文的原文规定，也不是一个已经验证的统一学术标准。

1. **先写一个可检查的命题。** 例如“独立重排优势字段会在 shape 不变时破坏样本对应”。图中每个对象都服务这个命题。
2. **保留必要的机制密度。** 在状态、对象身份、索引/维度、条件、动作中选最重要的几项。优先添加前后状态或对照，之后才加一句短解释。
3. **比较图保持共同骨架。** 两侧相同位置表示同类对象，颜色身份不随移动改变，只高亮真实差异。
4. **颜色承担语义。** 正常数据可用蓝，修复或备选路径可用青，异常用砖红；不是每个框都必须有不同颜色。必须同时用文本、线型或形状表达差异，避免只靠颜色。
5. **明确箭头类型。** 数据流用实线有向箭头，控制/依赖可用虚线箭头；时间参考线无箭头，含义应由图注说明。交叉箭头只有在交换机制需要时使用。
6. **图内短标签，图外说明条件。** 图号、结论、例外和环境放 caption；图内保留读图必要的变量和操作。采用 `(a)/(b)` 等子图标记即可，不叠加大标题和底部总结条。
7. **机制图与结果图区别对待。** 机制图允许概念布局并标注非比例；结果图必须有测量数据、坐标、单位、配置和来源。没有证据就不加性能柱状图。
8. **按真实使用宽度验收。** 在博客宽度检查字是否清楚、各部件是否可区分、是否能不看正文追踪一次变化。准确文字/公式/连线优先使用确定性矢量绘制；位图生成后仍需逐项校对。

“增加 30% 信息”应视为密度目标，而不是增加 30% 字数。可以增加一个重要状态和一组对照，减少重复解释；不要用编造的数字、随机图标或多余边框填充空白。

## 5. 可复用的简短设计提示

```text
Create a publication-quality technical mechanism figure, not a presentation poster.
Claim: [one precise claim].
Show: [entities, identity, before/after state, operation, invariant].
Use aligned subfigures for comparisons and shared geometry for unchanged components.
Restrained semantic colors, fine consistent lines, concise readable labels.
Encode information through structure and correspondence, not explanatory paragraphs.
Put qualifications in the caption. No invented measurements or decorative elements.
Verify every index, shape, arrow destination and state transition.
```

## 6. 第二轮研究：从“规范流程图”到视觉机制表达

本轮由用户对 PPO/GRPO 演示图的评价触发。重点从“有哪些规范”转向“怎样让机制本身形成有辨识度的构图”。新增原图均下载并渲染检查；其引用索引补充见[证据记录](arxiv-figure-style-citation-evidence.md)，不将本次未达到门槛的索引记录包装为已核实高引用。

### Mamba Figure 1：对象形态与路径共同构成主画面

输入输出为分格向量，状态采用展开形态；主状态路径、输入依赖的选择路径和离散化关系通过位置与线型区分。图的视觉中心是状态转移，参数不是一排尺寸相同的流程框。[原图：v2，PDF 第 3 页](https://arxiv.org/pdf/2312.00752v2#page=3)

本次观察：可以用矩阵、向量、轨迹和通道等有领域含义的形态增加表现力。立体叠层或多线条必须表达真实结构，不应作为任意张量的装饰。借鉴其语法，不复制其模型机制。

### DPO Figure 1：比较复杂度也可以用构图表达

左侧 RLHF 包含奖励建模与采样/打分循环，右侧 DPO 的路径更紧凑。响应对、模型形态和循环线配合浅色分区，比较对象不需要逐个套入相同方框。图注解释理论关系。[原图：PDF 第 2 页](https://arxiv.org/pdf/2305.18290#page=2)

本次观察：共用比较尺度并不要求两边机械镜像；差异可以通过支路数量、路径长度与循环结构表达。DPO 图中的示意图标服务偏好数据这一主题，不能拿奖杯等符号作为所有技术图的通用装饰。该图属于概念概述，不据此省略真实实现所需的 reference 或其他计算。

### GPipe Figure 2：时间与空白本身是信息

子图分别表达设备分区、朴素模型并行和 microbatch 流水。计算块的颜色、位置和交叠关系显示执行结构；空白区域使空泡可见，无需给每个空闲区都加一句解释。[原图：PDF 第 3 页](https://arxiv.org/pdf/1811.06965#page=3)

本次观察：需要讲调度时应优先画共享时间轴上的块，而不是“计算 → 等待 → 计算”的文字流程。空白只有对应空闲、边界或比较分隔时才有解释力；大片没有含义的留白不自动等于高级。

## 7. 对上一张 PPO/GRPO 演示图的具体复盘

对象：本次自绘的 PPO/GRPO 演示图，主题参照 [DeepSeekMath](https://arxiv.org/abs/2402.03300)，但下面评价的不是原论文。自绘图使用两个横向流程，颜色分角色，带 GAE 与组相对优势公式。

| 存在的问题 | 为什么影响表达 | 下一轮设计约束 |
| --- | --- | --- |
| 大标题与两行阶段标题占据过多高度 | 主画面显得像课件，视觉关注点分散 | 图内仅留短比较标签；完整题目与条件放 caption |
| 模块多为同形同大小圆角矩形 | 采样、模型、标量和向量难以从形态区分 | 回答用 token/轨迹，模型用紧凑模块，reward 用数值或标量节点 |
| 上下重复 prompt、旧策略、更新等描述 | 信息没有新增，增加阅读负担 | 共同结构压缩为输入与输出锚点，中间放大差异 |
| GAE/Critic 与组内计算没有足够强的几何区别 | 关键算法差异靠文字才能看见 | token 轴的价值/TD 对照与 response 轴的组间比较并置，显式区分两条轴 |
| 多处文字重复“奖励”“生成的回复”“优势估计” | 标签稀释主要信息 | 每个对象只命名一次，额外说明必须提供条件或机制 |
| `V(q,o)` 标签过于粗略 | 容易误解 value 可读取尚未生成的未来 token | 按 token prefix/state 定义 critic 输入；教学省略在 caption 明确 |
| 没有手算实例 | 公式存在，却不易建立优势符号的直觉 | GRPO 可用三条回复、可复核 reward/advantage 值；标明教学数据 |

表中的约束是下一轮候选设计，尚未重绘或验收。尤其不要将序列组优势和 token 级 GAE 画成同一个归约维度。

## 8. 下一张图的设计与检查方式

先做构图选择，再写生成提示词。对照题优先比较三种候选：同构结构、共享输入分叉、以数据对象为中心的局部放大。根据命题选一种，不默认套两行方框。

- **视觉中心**：图中必须有一个占据主要面积、能直接看出机制差别的区域；共同部分降低视觉权重。
- **图形语义**：矩阵、序列、组、时间、模型各有明确形态；去掉标签后仍能看出对象类别。
- **层级与节奏**：标题、子图名、操作标签、注释分层；按输出宽度保证阅读，不靠大标题制造层级。
- **色彩对应**：语义不同才换色，浅背景用于组边界，饱和色只强调关键操作；颜色之外有形状或文字区分。
- **标签预算**：同一事实只出现一次；图注承担条件、例外与省略，不把每块区域都写成教学段落。
- **技术验收**：核对输入、输出、箭头方向、索引与归约轴；手算例子逐项复核。漂亮不能掩盖不正确的机制。
- **审美验收**：正常博客宽度可读；第一眼定位主要对照；空白有用途；没有无关图标、随机渐变或统一圆角框堆积。

这些是本次学习形成的可执行检查项。不能用“publication-quality”“学术风格”等提示词代替具体布局和对象编码，也不将一次生成成功等同设计能力已验证。
